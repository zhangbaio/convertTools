# 红果免签名机接入

给其他项目用的接入说明。搜索、剧集列表、播放地址都不需要模拟器、Frida 或 unidbg。按下面三步调用本仓库的 `pure_sign.py` 和 `playback_guest.py` 即可。

2026-06-29 的《红果脱机下载-端到端》把 unidbg 签名写成前置条件。那条只对官方 App 的 `multi_video_model/preload/v1` 成立。本文的三个接口用另一套校验，不要再部署签名机。

依赖：Python 3.10+，`requests`，`pycryptodome`。搜索和剧集列表的签名用标准库 `hashlib` 的 SM3（OpenSSL 3，Ubuntu 22.04 的系统 Python 已满足）。

## 链路

| 步骤 | 模块 | 网关认什么 |
| --- | --- | --- |
| 搜索、剧集列表 | `pure_sign.py` | 进程内 PureSign。`device_id` 为 10–20 位数字并持久保存 |
| 播放地址 | `playback_guest.py` | `device_register` 下发的 `device_id` + `iid`。请求本身不带六神签名 |
| 下载后解密 | `offline_decrypt.py` | CDN 是 CENC。用轨道里的 `spade_a` 解出内容密钥 |

三步的 host 和身份不要混用。播放地址在 `api5-normal-sinfonlineb`，搜索和剧集列表在 `api5-normal-sinfonlinea`。

```
搜索 ──series_id──▶ 剧集列表 ──vid──▶ 播放地址 ──main_url + spade_a──▶ 下载并解密
```

搜索结果里有时已经带第一集 `vid`，可以跳过剧集列表，直接要播放地址。

## 1. 搜索和剧集列表

算法在 `pure_sign.py`。它来自 jackotom/hongguo-drama 的 `src/native/app-source.js`（GPL-3.0），经 N3urda/hongguoTV、woshishiq1/drpys 传到 sunnysky123/hongguo-web 的 `server/src/core/pure-sign.js`。桌面端 ShortDramaProcessor 的 NOTICE 指向同一实现。拷贝该文件时保留文件头说明，不要把它标成 MIT。

`device_id` 用 `pure_sign.load_device_id(path)` 生成一次并落盘。10–20 位数字即可，不需要向 `device_register` 注册，也不要每次请求换一个。不传 `iid`。若要传，必须是这台设备注册时的 `install_id`；随便填一个会得到空包。模拟器里红果当前设备的 `device_id`（单独用，或配上它自己的 `iid`）实测同样可用。

签名对 query 和 body 字节敏感：最终发出的 URL 必须和送进 `pure_sign.sign` 的字符串一致，body 用 `json.dumps(..., separators=(",", ":"), ensure_ascii=False)` 的 UTF-8。query 转义与 `encodeURIComponent` 相同，保留字符是 `-_.!~*'()`。

`pure_sign.branch_of(url, body, khronos) == 1` 时服务端不认。把 `_rticket` 加 1 后重签，最多 32 次。`khronos` 是秒，`_rticket` 是毫秒，两者独立。空 body 或 JSON 解析失败时换新的 `_rticket` 再试，最多 3 次，间隔 0.4 秒。剧集列表返回 `code=0` 但没有 `video_list` 时同样重试，这是软风控，大约三分之一的请求会遇到。

公共 query 按这个顺序拼，然后再加业务参数和 `_rticket`：

| 参数 | 值 |
| --- | --- |
| aid | 8662 |
| app_name | novelread |
| version_code | 72232 |
| version_name | 7.2.2.32 |
| channel | audit |
| device_platform | android |
| device_type | audit-windows |
| os_version | 12 |
| update_version_code | 72232 |
| device_id | 本地持久化的 16 位数字 |

固定请求头：

| 头 | 值 |
| --- | --- |
| user-agent | hongguo-web/1.0 |
| x-tt-store-region | cn-sh |
| x-tt-store-region-src | uid |
| passport-sdk-version | 5051452 |
| sdk-version | 2 |
| content-type | application/json; charset=utf-8 |

有 body 时再加 `x-ss-stub`，值为 body 的 MD5，大写十六进制。签名头用 `pure_sign.sign` 的返回值原样合并：`x-gorgon`、`x-khronos`、`x-ladon`、`x-argus`、`x-helios`、`x-medusa`。不要带 `x-tt-token` 和 cookie。

### 搜索

`GET https://api5-normal-sinfonlinea.fqnovel.com/reading/bookapi/search/tab/v`

业务 query：`query`、`tab_name=feed`、`search_source=1`、`offset`、`count=10`、`use_correct=true`。翻页把上一页的 `passback`、`search_id` 原样带回，`offset` 用 `next_offset`。`has_more` 为假或本页没有数据就停止。

短剧在 `search_tabs[0].data[]`。没有 `episode_cnt` 的条目丢掉。建议字段：

| 字段 | 来源 |
| --- | --- |
| series_id | `book_id`，否则 `search_result_id` |
| title | `search_high_light.title.text`，去掉 HTML；否则 `video_detail.series_title` |
| episode_cnt | `video_detail.episode_cnt` 或 `video_data` 里的同名字段 |
| vid | `video_data.vid`，有则是第一集，可直接要播放地址 |
| cover | `video_data.cover` |

`video_data` 可能是对象，也可能是只含一个对象的数组。

### 剧集列表

`POST https://api5-normal-sinfonlinea.fqnovel.com/novel/player/multi_video_detail/preload/v1`

路径没有末尾斜杠。body 用 `pure_sign.episodes_body(series_id)`，键顺序要保持：`biz_param`、`dr_scene=preload`、`series_id`。`series_id` 可以用逗号拼多个，一批 20 个是稳定的。

读 `data[series_id].video_data`。每集在 `video_list[]`：`vid_index`、`vid`、`title`、`duration`、`episode_cover`。整剧用 `series_title`、`series_intro`、`episode_cnt`、`series_status`（1 为完结）、`series_cover`。

## 2. 播放地址

实现在 `playback_guest.py`。注册包络来自 hongguo-web 的 `playback-device.js`，其上游是 tsukiyo-zero/hongguoTV 的 `DeviceRegister.kt`（GPL-3.0）。拷贝时保留这个来源。

```python
import playback_guest

models = playback_guest.video_models(["7700944149695958078"])
track = models["7700944149695958078"]["video_list"][0]
url = track["main_url"]
spade = track["encrypt_info"]["spade_a"]
definition = track["video_meta"]["definition"]
```

`video_models` 返回 `{vid: video_model}`。身份缓存在进程里；空包或缺少 `video_model` 时重新注册再试一次。调用方不要打印 `device_id` 和 `iid`。

注册：

- `POST https://log5-applog-lf.fqnovel.com/service/2/device_register/?tt_data=a&cronet_version=8d40f833_2026-03-03&ttnet_version=4.2.243.31-douyin&use_store_region_cookie=1`
- Body 是 ttEncrypt 包络：6 字节 `746305100000`，32 字节随机数，然后是 AES-128-CBC。明文是 `sha512(gzip(json)) + gzip(json)`，PKCS7 填充。密钥材料由随机数和文件里的盐做两轮 SHA-512。
- 注册 JSON 的版本是 `73932` / `7.3.9.32`，包名 `com.phoenix.read`，`aid` 8662。
- 成功时读 `device_id_str` 和 `install_id_str`，`code` 为 0。

取播放地址：

- `POST https://api5-normal-sinfonlineb.fqnovel.com/novel/player/multi_video_model/v1/`
- query 用文件里的 `DEVICE_BASE`，版本是 `71332` / `7.1.3.32`。这个版本和注册版本不一致，按这个差异发。`resolution` 含 `*`，转义时 `safe` 为空。顺序固定：先 `DEVICE_BASE`，再 `device_id`、`iid`、`_rticket`。
- 不带 `X-Argus`、`X-Gorgon` 等签名头，也不带 token、cookie。
- body 的 `mixed_video_id_map` 键是 `"1004"`，值是 vid 数组。`biz_param.device_level` 为 3，`need_all_video_definition` 为 true。不要加 `dr_scene`。
- 一批建议不超过 5 个 vid。
- `data[vid].video_model` 可能是 JSON 字符串。`video_list` 可能是对象，要改成数组再用。

随机拼的 `device_id` / `iid` 会得到 HTTP 200 和空 body。带上六神签名的请求，这条 `/v1/` 也不接受。官方 App 的 `/novel/player/multi_video_model/preload/v1/` 才认 `libmetasec`，那是另一条接口，接入时不要走。

轨道字段：

| 字段 | 用途 |
| --- | --- |
| `video_meta.definition` | `360p` / `480p` / `540p` / `720p` / `1080p` |
| `video_meta.size` | 字节数 |
| `video_meta.codec_type` | `bytevc1` 或 `bytevc2` |
| `main_url` | CDN 地址，可直接 GET |
| `encrypt_info.spade_a` | 交给 `offline_decrypt.offline_decrypt` |
| `encrypt_info.kid` | 密钥标识，解密函数自己从 `spade_a` 取内容密钥 |

实测一部剧的 5 档清晰度都有 `main_url` 和 `spade_a`。360p–720p 经常是 `bytevc2`，1080p 多为 `bytevc1`。解密后 `bytevc1` 变成 `hvc1`，容器里的 `encv` 会去掉。PyAV 往往解不了 `bytevc2`，要播就优先下 1080p。解密细节见 `docs/VIDEO_DECRYPTION_RE.md` 和 `offline_decrypt.py`。

## 3. 最小调用

把 `pure_sign.py`、`playback_guest.py` 放到同一目录。下面的脚本只依赖这两个文件。

```python
import hashlib, json, time
import requests
import playback_guest
import pure_sign

def audit(method, path, body=None, extra=None):
    device_id = pure_sign.load_device_id("audit_device.json")
    data = None
    headers = pure_sign.session_headers()
    headers["content-type"] = "application/json; charset=utf-8"
    if body is not None:
        data = json.dumps(body, ensure_ascii=False, separators=(",", ":")).encode()
        headers["x-ss-stub"] = hashlib.md5(data).hexdigest().upper()
    rticket = int(time.time() * 1000)
    last = None
    for attempt in range(3):
        khronos = int(time.time())
        url, rticket = pure_sign.build_url(path, extra, device_id, rticket)
        guard = 0
        while pure_sign.branch_of(url, data, khronos) == 1 and guard < 32:
            guard += 1
            rticket += 1
            url, rticket = pure_sign.build_url(path, extra, device_id, rticket)
        sent = dict(headers)
        sent.update(pure_sign.sign(url, data, khronos))
        try:
            r = requests.request(method, url, data=data, headers=sent, timeout=30)
            if not r.content.strip():
                raise ValueError("empty body")
            j = r.json()
            if j.get("code") not in (0, None):
                raise RuntimeError("code=%s" % j.get("code"))
            return j
        except Exception as e:
            last = e
            rticket += 1
            if attempt < 2:
                time.sleep(0.4)
    raise last

def search(query):
    j = audit("GET", "/reading/bookapi/search/tab/v", extra={
        "query": query, "tab_name": "feed", "search_source": "1",
        "offset": "0", "count": "10", "use_correct": "true",
    })
    return (j.get("search_tabs") or [{}])[0].get("data") or []

def episodes(series_id):
    j = audit("POST", "/novel/player/multi_video_detail/preload/v1",
              body=pure_sign.episodes_body(series_id))
    return ((j.get("data") or {}).get(str(series_id)) or {}).get("video_data") or {}

cells = search("长公主")
series_id = str(cells[0]["book_id"])
video_data = episodes(series_id)
vid = str(video_data["video_list"][0]["vid"])
model = playback_guest.video_models([vid])[vid]
print(len(video_data["video_list"]), len(model["video_list"]))
```

本仓库里 `hongguo.search`、`hongguo.get_episodes`、`playback_guest.video_models` 已经按这个顺序接好。前两个在新链路失败时会退回旧的 unidbg 签名。其他项目如果没有签名机，退回分支会直接失败，以本文的异常为准。

不打印 `device_id`、`iid`、签名头和 `spade_a`。用一部已知剧看数量和布尔值：
